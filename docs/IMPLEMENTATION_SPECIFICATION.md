# Implementation specification for the compact DAiSEE workflow

This specification describes recovered source code and archived records for the 960-clip study. It does not certify an exact historical software environment or a previously untouched Test set. Source files are preserved separately from new revision helpers.

## Corpus construction and inputs

The builder reads TrainLabels.csv, ValidationLabels.csv and TestLabels.csv. It validates codes 0–3 and derives a participant identifier from the first six characters of the clip basename. Within each supplied partition, it groups rows by the joint four-label tuple. When the budget permits, it assigns one clip per observed tuple, allocates the remaining capacity proportionally using a largest-remainder rule, and selects clips using seed-dependent SHA-256 ordering and participant round-robin traversal within each tuple. It outputs 600/160/200 rows for Train/Validation/Test. Selection uses the labels of each partition, including Test labels for Test subset composition. This is not a claim that Test labels were used to fit the classifier. It changes the interpretation of the target evaluation sample and must be disclosed. Reproducing subset selection from source labels still requires the exact accessed source files, whose hashes were not recovered.

The archived manifest and final prediction IDs have been verified against each other. There are 68/17/20 participant identifiers in Train/Validation/Test and no identifier overlap. The six-character identifier convention has not been independently validated by visual identity inspection.

## Frame sampling and input transformation

Both mean and sequence extractors seek integer indices generated by `np.linspace(0, frame_total - 1, 6, dtype=int)`. The endpoints are included. Indices can repeat for a video with fewer than six frames; the code does not prohibit this. OpenCV decodes frames and converts BGR to RGB. The full decoded frame is processed. There is no face detector, landmark extractor, face crop or facial alignment in this original workflow.

The source requests `ResNet18_Weights.DEFAULT` and uses `weights.transforms()` on channel-first uint8 tensors. Official torchvision documentation identifies DEFAULT as IMAGENET1K_V1 and documents a 256-pixel short-side resize, bilinear interpolation, a 224-pixel centre crop, conversion to [0,1], and normalization with channel means [0.485,0.456,0.406] and standard deviations [0.229,0.224,0.225]. The original torchvision version and resulting transform defaults, including antialiasing, were not recorded in the recovered files. These documented transforms must not be presented as independently observed original runtime parameters beyond what the source establishes.

The encoder removes the final fully connected layer, retaining global average pooling. Flattening its output yields 512 features per frame. It runs in eval mode under `torch.inference_mode()`, with no encoder training. The recorded run metadata gives six frames and CPU execution. Batch size 4 is in the manuscript command; an original run record independently confirming batch size was not recovered.

Failure handling differs between the archived extractors. The mean extractor skips failed requested frames if at least one frame decodes. The sequence extractor aborts if any requested frame fails. Neither script writes per-frame decode logs. Consequently, successful completion of mean extraction alone does not establish that every original clip contributed exactly six successfully decoded frames. Do not silently describe a newly tightened failure rule as the original one.

## Representations

Let h_t be the 512-dimensional embedding at sampled frame t, with T=6.

- Mean: average of h_t over t; 512 dimensions.
- Temporal block 1: the same mean.
- Temporal block 2: embedding-wise population standard deviation, NumPy ddof=0.
- Temporal block 3: h_6 minus h_1, preserving the sign.
- Temporal block 4: the average of |h_(t+1) minus h_t| over the five consecutive sampled-frame pairs, independently in each embedding coordinate.

Concatenate the four temporal blocks in that order to obtain 2048 dimensions. Mean absolute change is not mean absolute deviation and should not be denoted ambiguously as MAD without expansion. This summary is not a learned temporal network.

The compressed mean archive uses X with shape [960,512], whereas the sequence archive uses X with shape [960,6,512], both float32, together with clip_id, split and the four integer label arrays. The final script requires mean and sequence clip_id and split arrays to be exactly aligned. Additional alignment/label checks are provided by the new verification helper.

## Validation selection and fitting partitions

The recovered tuned mean-search loop fits StandardScaler and LogisticRegression only on the 600 Train clips. It tests C in {0.01,0.1,1,10,100} and class_weight in {balanced,None}. Selection sorts by macro-F1, then weighted-F1, then smaller C. Any remaining exact tie retains iteration order. All selected mean candidates in the archived validation_search.csv are balanced.

The temporal-validation script fits StandardScaler, PCA with 128 components and whiten=True, and balanced LogisticRegression on Train only. It tests C in {0.001,0.01,0.1,1,10}. Selection uses macro-F1, then weighted-F1, then the first encountered ascending C. The requested component count is capped by the fitting sample count minus one and the feature dimension. Neither scaler nor PCA is fitted on Validation during candidate selection.

The archived validation results support mean features for Boredom, Engagement and Confusion, and temporal features for Frustration. The respective selected C values are 10, 0.1, 0.1 and 1. The temporal-minus-best-mean validation F1 differences are -0.006682, -0.007497, -0.068992 and +0.026587. The first two differences are small; they are selection outcomes, not demonstrations of statistically significant representation superiority. The search spaces differ across representations. The historical cross-representation exact-tie rule was not documented, and there is no exact tie in these records. A retrospective replay that encounters such a tie stops instead of inventing a historical rule.

The final script refits the selected pipeline on all 760 Train+Validation clips. The scaler is refitted on those clips; the 128-component whitened PCA is also refitted there for Frustration only. Test is excluded from fitting. It is used to generate the archived final predictions. Additional analysis uses those fixed predictions without changing the model.

## Classifier and unspecified defaults

The final source sets LogisticRegression(C=selected_C, class_weight='balanced', max_iter=5000, random_state=20260928). Balanced weights are recomputed from the labels in the current fitting partition; the usual definition is n_samples divided by (n_present_classes times class_count). This is not a set of weights estimated on Test.

The source does not explicitly set solver, penalty, tol, fit_intercept or multi_class. For example, scikit-learn 1.5 documents lbfgs, L2, tol=1e-4 and fit_intercept=True. This versioned reference is an interpretation aid, not evidence that the original run used 1.5. PCA also leaves svd_solver at the library default. Exact original package versions are therefore needed to resolve all defaults unambiguously. The archived code does not establish actual optimizer iteration counts or that convergence warnings were absent.

All reported final classification metrics fix labels [0,1,2,3] with zero_division=0. The archived script's confidence intervals were 1000 clip-stratified bootstrap replicates; those must not be described as participant-cluster intervals. Revision phase 2 separately computes 2000 participant-cluster replicates and documents their limitations.

## Historical Test use

An earlier predictions.csv contains Test predictions for the same 200 clips and four tasks, with the same true labels as final_selected_predictions.csv. Its predictions differ in 57/65/34/105 clips for Boredom/Engagement/Confusion/Frustration, respectively. Earlier metrics.csv also contains Test metrics. These files were archived before the final-selected files. Together they establish more than one recorded Test prediction set and invalidate an unqualified claim that Test was evaluated only once across the whole study.

This finding does not by itself establish that final configuration selection was based on Test performance. The archived validation tables are consistent with the reported selections. Nevertheless, the later evaluation cannot be presented as an untouched prospective test based solely on the current evidence. The final_protocol.json Boolean and its post-evaluation timestamp do not erase earlier Test access. E1–E4 remains an undocumented naming scheme, not a verified list of exactly four executions.

## Environment and resources

The original exact versions of Python, NumPy, pandas, matplotlib, SciPy, scikit-learn, torch, torchvision, OpenCV and Pillow were not recovered. Broad requirements in the old archive are compatibility constraints, not an exact lock file. No historical package version is inferred from the date or replaced with the environment used for current helper verification.

The user previously reported an Intel Core i7-6700HQ CPU and approximately 15.9 GB RAM; recovered metadata specifies CPU computation. Original extraction time, training time, process peak memory and exact weight-file checksum are not available. Current helper verification timing is not a substitute for those measurements. Float32 array payloads can be calculated exactly: mean embeddings require 1.875 MiB, sequence embeddings 11.25 MiB, and the raw temporal summary 7.5 MiB, excluding metadata, copies, model weights and process allocations. These are not measured RAM requirements. The compact video folder was user-reported as approximately 1.6 GB, not measured in this revision.
